# 项目复盘

这个项目来自一次企业员工数补全需求。

客户手里有一批企业名单，希望导入 Excel 后自动补出近几年的员工数，最后还是以 Excel 形式交付。第一眼看，这像是一个普通的页面采集脚本；真正做起来以后，我发现要解决的是一整条本地交付链路。

## 一开始的判断

我先把任务拆成四块：

- 输入 Excel 读取和字段保留。
- 本机浏览器登录态复用。
- 页面解析和异常分类。
- 进度保存和结果导出。

这样做的原因是，真实批量任务不可能只关注成功路径。输入字段可能不标准，页面可能变化，账号状态可能需要人工处理，运行也可能中断。

## 中间的转折

最关键的转折是从一次性脚本改成可恢复的本地工具。

如果只写一个从 Excel 到 Excel 的脚本，确实很快。但一旦中途失败，用户只能重新跑。后来我把进度写进 SQLite，每一行都有状态，成功记录默认跳过，失败记录可以导出复核。

第二个转折是保留浏览器可见性。这个项目允许用户用本机浏览器完成登录或人工确认。对交付项目来说，这比纯粹炫技更可靠。

## 最后怎么验收

我主要看三件事：

- 输入样例能稳定读取，字段不丢。
- 采集过程中断后可以继续跑。
- 导出的 Excel 能清楚区分成功、未匹配、无员工数、验证提示、页面异常等状态。

公开版本保留了这些核心逻辑和测试，但去掉了真实数据、运行日志、浏览器缓存和客户交付文档。
